# AGENTS.md — ResearchLog

[简体中文](AGENTS.md) | English

This directory contains **ResearchLog**, a standalone desktop app for research project management, goals, and progress logs.
If you are an agent asked to manage the research log (Codex / Claude / other), operate on the data **only through `rlog.cmd`**.

## Rules

1. **Use `rlog.cmd`; do not edit `data/research-log.json` directly.** The CLI handles atomic writes, daily backups, revision numbers, and field normalization.
2. If the user explicitly asks you to edit the JSON directly: keep `schemaVersion`, `rev`, `updatedAt`, `projects[].id`, and `milestones[].id`; write the complete file as UTF-8; increment `rev` by 1.
3. **Never remove `rev`**, and do not create new top-level fields.
4. Projects and milestones are matched by name; if names are ambiguous, the CLI reports candidates — use a longer name or an id.
5. `delete-project` is irreversible and requires `--yes`; confirm with the user first.
6. The app does not need to be open. The CLI writes the file directly; an open window refreshes within about one second.
7. Timestamps, ids, and completion times are generated by the program; never fill them in yourself.

## Commands

```text
rlog.cmd list [--status active|planned|paused|done|all] [--json]
rlog.cmd show <project> [--json]
rlog.cmd add-project <title> [--field field] [--goal goal] [--criteria criteria] [--target-date YYYY-MM-DD] [--status planned|active|paused|done]
rlog.cmd rename <project> <new title>
rlog.cmd status <project> <planned|active|paused|done>
rlog.cmd goal <project> [--text ...] [--criteria ...] [--target-date ...]
rlog.cmd add <project> <milestone> [--due YYYY-MM-DD] [--note note]
rlog.cmd done <project> <milestone>
rlog.cmd undone <project> <milestone>
rlog.cmd rm <project> <milestone>
rlog.cmd note <progress text> [--project project] [--global]
rlog.cmd delete-project <project> --yes
rlog.cmd export md|json [--out file]
rlog.cmd where
```

- `--json` can appear anywhere and prints machine-readable output.
- `--data <dir>` temporarily uses another data directory (for tests).
- Exit code: 0 on success, non-zero on failure (error in stderr or the JSON `error` field).

## Common requests → commands

| User says | Run |
|---|---|
| Add a milestone "run baseline" to "Single-cell" | `rlog.cmd add "Single-cell" "run baseline"` |
| Check off "run baseline" in "Single-cell" | `rlog.cmd done "Single-cell" "run baseline"` |
| Log progress: "tuned the parameters today" | `rlog.cmd note "tuned the parameters today" --project "Single-cell"` |
| Create a future project | `rlog.cmd add-project "Gut microbiome" --status planned --goal "..."` |
| Mark this project done | `rlog.cmd status "Single-cell" done` |
| What did I do this week? | `rlog.cmd list --json`, then `rlog.cmd show "<project>" --json` as needed |

## MCP (optional)

`tools/mcp_server.py` exposes the same capabilities as MCP tools: `log_list`, `log_show`, `log_create_project`, `log_add_milestone`, `log_check_milestone`, `log_add_note`, `log_set_status`, `log_set_goal`, `log_rename_project`, `log_delete_milestone`, `log_delete_project`, `log_export`.

If the current client has `research_log` connected, prefer those tools; otherwise use `rlog.cmd`. See `docs/en/mcp.md` for configuration.

## Desktop app

`run.cmd` (source) or `科研日志.exe` (Release) starts the desktop window and the local engine. The CLI works without opening the window. See `README.md`.
