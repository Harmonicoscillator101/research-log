# Data Format

[简体中文](../data-format.md) | English

All ResearchLog data lives in one UTF-8 JSON file, by default `data/research-log.json`. The app writes it atomically; **manual editing is not recommended**. If you must edit it, back it up first and respect the invariants below.

## Top level

```jsonc
{
  "schemaVersion": 1,
  "rev": 12,
  "updatedAt": "2026-11-24T20:00:00+08:00",
  "projects": [],
  "entries": []
}
```

| Field | Type | Notes |
|---|---|---|
| `schemaVersion` | number | Data structure version; currently `1` |
| `rev` | number | Incremented on every write; used by the frontend to detect new revisions |
| `updatedAt` | string | ISO 8601 timestamp with timezone |
| `projects` | array | Projects |
| `entries` | array | Progress entries (optionally linked to a project) |

## Project `projects[]`

```jsonc
{
  "id": "pabc123",
  "title": "Sample: Protein folding model",
  "field": "Biophysics",
  "status": "active",
  "goal": {
    "text": "Build a reproducible simplified model of protein folding and submit a methods paper.",
    "criteria": "The paper is submitted and accepted.",
    "targetDate": "2027-06-30"
  },
  "milestones": [],
  "notes": "",
  "createdAt": "2026-11-01T09:00:00+08:00",
  "updatedAt": "2026-11-24T20:00:00+08:00",
  "startDate": "2026-11-01",
  "targetDate": "",
  "completedAt": null,
  "archived": false,
  "order": 0,
  "resources": []
}
```

| Field | Type | Notes |
|---|---|---|
| `id` | string | Stable project id generated by the app |
| `title` | string | Project name; duplicates are allowed (CLI uses a longer name or id) |
| `field` | string | Optional field tag |
| `status` | enum | `planned` / `active` / `paused` / `done` |
| `goal.text` | string | One-sentence main goal |
| `goal.criteria` | string | Optional success criteria |
| `goal.targetDate` | string | Optional `YYYY-MM-DD` |
| `milestones` | array | Milestones |
| `notes` | string | Optional project-level note |
| `createdAt` / `updatedAt` | string | ISO timestamps |
| `startDate` | string | Optional start date |
| `targetDate` | string | Optional project target date |
| `completedAt` | string/null | Completion time |
| `archived` | bool | Archive flag (not used by the UI yet) |
| `order` | number | Board order; smaller comes first |
| `resources` | array | Attached resources |

## Milestone `projects[].milestones[]`

```jsonc
{
  "id": "mabc123",
  "text": "Reproduce the baseline case",
  "done": false,
  "doneAt": null,
  "due": "2026-12-01",
  "note": "Align the equilibrium state first, then add the perturbation.",
  "order": 0
}
```

| Field | Type | Notes |
|---|---|---|
| `id` | string | Milestone id |
| `text` | string | Content |
| `done` | bool | Completed |
| `doneAt` | string/null | Completion time |
| `due` | string | Optional `YYYY-MM-DD` |
| `note` | string | Optional note |
| `order` | number | Order within the project; smaller comes first |

## Progress entry `entries[]`

```jsonc
{
  "id": "eabc123",
  "projectId": "pabc123",
  "at": "2026-11-24T19:30:00+08:00",
  "kind": "note",
  "text": "Checked the collision operator against the literature; baseline error 0.3%."
}
```

| Field | Type | Notes |
|---|---|---|
| `id` | string | Entry id |
| `projectId` | string/null | Linked project; `null` means a global entry |
| `at` | string | Timestamp |
| `kind` | enum | `note` (user) / `auto` (generated, e.g. "completed a milestone") |
| `text` | string | Plain text (copyable in the UI) |

## Resource `projects[].resources[]`

```jsonc
{
  "id": "rabc123",
  "path": "D:\\papers\\example.pdf",
  "kind": "file",
  "label": "example.pdf",
  "addedAt": "2026-11-24T19:00:00+08:00",
  "category": "ref"
}
```

| Field | Type | Notes |
|---|---|---|
| `id` | string | Resource id |
| `path` | string | **Absolute path**; the app never copies the file |
| `kind` | enum | `file` / `dir` |
| `label` | string | Display name; defaults to the file name |
| `addedAt` | string | Attach time |
| `category` | enum | `ref` (papers) / `repo` (repositories) / `note`; missing means `ref` |

## Invariants

1. `schemaVersion`, `rev`, and `updatedAt` must exist; each write increments `rev`;
2. All `id` values are unique within the file and stable; do not reuse deleted ids;
3. `status` is one of four enum values; `category` is one of three;
4. Timestamps use ISO 8601 with timezone; dates use `YYYY-MM-DD`;
5. Resource `path` must be absolute; relative paths are normalized on read;
6. The file must be UTF-8 (BOM allowed) and contain one complete JSON object.

## Versioning and migration

`schemaVersion` is currently `1`. If the structure changes:

- fill defaults in `Store.normalize()` for backward compatibility;
- keep reading old fields for at least one major version;
- document the migration in `CHANGELOG.md` and this file;
- back up automatically before migrating.

## Backups

- Before the first write of each day, the old file is copied to `data/backups/research-log-YYYY-MM-DD.json`;
- The last 14 days are kept; older backups are removed;
- A backup has the same format as the main file and can be restored by renaming it.
